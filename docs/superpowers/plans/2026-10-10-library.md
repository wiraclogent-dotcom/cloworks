# Library Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A workspace-shared `/library` page under Tools: categorised links with pinning, an Updated/New badge and an
optional brand tag, editable by ADMIN and LEAD.

**Architecture:** Two new workspace-scoped Prisma models. Pure core functions in `src/lib/library.ts` (take a scoped
db + actor, throw `LibraryError`) are wrapped by result-object server actions in `src/app/(app)/library/actions.ts`,
following the `projects` pattern. A server page loads everything once; a client view filters in the browser.

**Tech Stack:** Next 16 (App Router, cacheComponents), React 19, Prisma 6 / Postgres, zod 4, Tailwind 4,
lucide-react, Vitest + Testing Library, embedded-postgres test DB (`tests/helpers/testDb.ts`).

**Spec:** `docs/superpowers/specs/2026-10-10-library-design.md`

## Global Constraints

- Read the relevant guide in `node_modules/next/dist/docs/` before writing Next code (AGENTS.md).
- Every new model carries `workspaceId String @default(dbgenerated())` + `@@index([workspaceId])` and is added to `SCOPED_MODELS` in `src/lib/db.ts`.
- Editors: `ADMIN` and `LEAD` only, via a new permission action `"library.manage"`.
- Title 1–120 chars; description ≤ 300 chars; URL must pass `isHttpUrl` (`src/lib/fieldSchema.ts`).
- Badge window: **14 days** on `contentUpdatedAt`. Labels: `New · 3 Oct` (never edited) / `Updated · 3 Oct`. Date format Jakarta, `d MMM`.
- Pin / reorder must NOT change `contentUpdatedAt`.
- Category delete refused while it has items, message: `Move or delete its links first`.
- Starter categories, in order: `Product Knowledge`, `Brand Guidelines (NG)`, `Master Box Size`, `Latest Updates`.
- Links open with `target="_blank" rel="noopener noreferrer"`.
- Server actions return result objects (never throw to the client), as in `src/app/(app)/projects/actions.ts`.

## Review Focus

1. **Cross-workspace ids** (category or brand id from another workspace passed to create/update) → `VALIDATION` field error, never a write. Test in Task 2.
2. **URL with whitespace / uppercase scheme** (`"  HTTPS://Drive.google.com/x "`) → trimmed and accepted; `javascript:alert(1)` and `ftp://` rejected. Test in Task 2.
3. **Deleted brand** referenced by an item → item stays, brand becomes null (`onDelete: SetNull`). Test in Task 1.
4. **Search with special characters / mixed case** (`"NG (2026)"`) → plain case-insensitive substring match, no regex errors. Test in Task 3.
5. **Moving the first item up / last item down** → no-op, no error, order unchanged. Test in Task 2.

### Task 2: Library core functions

**Files:**
- Create: `src/lib/library.ts`
- Test: `tests/library.test.ts` (add `describe("library cores")`)

**Interfaces:**
- Consumes: Task 1 models, `can`, `isHttpUrl`.
- Produces:
  ```ts
  export type LibraryErrorCode = "FORBIDDEN" | "VALIDATION" | "NOT_FOUND" | "CATEGORY_NOT_EMPTY";
  export class LibraryError extends Error { code; fieldErrors?: Record<string,string> }
  export type LibraryItemInput = { title: string; url: string; description?: string|null; categoryId: string; brandId?: string|null; pinned?: boolean };
  export type Actor = { id: string; appRole: AppRole };
  createItemWith(db, actor, input): Promise<{ id: string }>          // sortOrder = max in category + 1
  updateItemWith(db, actor, id, input: LibraryItemInput): Promise<void> // sets contentUpdatedAt = now, updatedById
  deleteItemWith(db, actor, id): Promise<void>
  setPinnedWith(db, actor, id, pinned: boolean): Promise<void>        // does not touch contentUpdatedAt
  moveItemWith(db, actor, id, dir: "up" | "down"): Promise<void>       // swaps sortOrder with neighbour in same category; no-op at ends
  createCategoryWith(db, actor, { name, icon? }): Promise<{ id: string }>
  updateCategoryWith(db, actor, id, { name, icon? }): Promise<void>
  moveCategoryWith(db, actor, id, dir: "up" | "down"): Promise<void>
  deleteCategoryWith(db, actor, id): Promise<void>                    // CATEGORY_NOT_EMPTY when items exist
  ```
  `db` type is `ScopedDb` (as other cores use).

- [ ] **Step 1: Write failing tests** (names → assertions):
  - `rejects non-editors on every write`: each function with `REQUESTER` and `CREATIVE` → code `FORBIDDEN`.
  - `validates title, url and description together`: `{ title:" ", url:"javascript:alert(1)", description: "x".repeat(301) }` → `VALIDATION`, `Object.keys(fieldErrors).sort()` = `["description","title","url"]`; `ftp://x` also rejected for `url`.
  - `trims and accepts mixed-case https`: url `"  HTTPS://Drive.google.com/x "` stored trimmed.
  - `rejects unknown or foreign category and brand`: ids from a second workspace (create via `db.raw.workspace.create`) → `VALIDATION` with `categoryId` / `brandId` field errors.
  - `pin and move leave contentUpdatedAt alone; edit bumps it`.
  - `move is a no-op at the ends` and `move swaps neighbours`.
  - `deleteCategory refuses a non-empty category` → `CATEGORY_NOT_EMPTY`, message `Move or delete its links first`; empty one deletes.
  - `duplicate category name` → `VALIDATION` field `name`.
  - unknown item id → `NOT_FOUND`.

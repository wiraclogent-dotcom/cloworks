## Defects
1. **Major** - No way to see in-app notifications. `/requests` etc.: nav has no bell/list and there is no notifications route (`find src/app -name page.tsx` has none). DB holds 7 Notification rows for Fadli (ASSIGNED, MENTION, STATUS) that nothing displays. README promises in-app notifications. Expected: a notifications list/badge. Files: src/lib/notify.ts, layout nav.
2. **Major** - Hydration mismatch console error on the board (every load as a mover): `aria-describedby="DndDescribedBy-0"` (client) vs `DndDescribedBy-N` (server), N increments per load. dnd-kit `useUniqueId` counter differs SSR vs client. Fix: pass a stable `id` prop to `<DndContext>`. File: src/components/Board.tsx:103. Repro: sign in as Wira/Fadli, open /requests, console.
3. **Minor** - DONE dialog Escape (and after a drop/keyboard drag) drops focus to `<body>` (activeElement = body/null); focus is not restored to the drag handle / Move control that opened it. Repro: drag a First look card to Done, press Escape. Keyboard-drag announcements (live region) use raw ids: "Draggable item cmuz3o2t... was moved over droppable area ON_PROGRESS." Files: src/components/Board.tsx and the done dialog component.
4. **Minor** - Illegal move/unassigned DONE messages use raw enums: "Cannot move request from ON_PROGRESS to DONE", "Request needs an assignee before it can be marked DONE". The board offers no hint what is allowed. File: src/lib/transition.ts:45-46 (map to statusLabels).
5. **Minor** - Board on a 1024px-wide desktop viewport: 4th column (Done) is cut off and needs horizontal scroll inside the board; Done is the most-checked column. File: src/components/Board.tsx layout (column min width).
6. **Minor** - Staged validation: first submit of /requests/new with empty title + bad URL + past deadline shows only title and brief errors; the past-deadline error appears only after fixing those (same on /projects/new: due-before-start appears after file link fixed). Likely cross-field `refine` skipped when base fields fail. Files: src/lib/submitRequest.ts, project schema.
7. **Minor** - Access-denied panels (/dashboard/team, /admin/*) are rendered with HTTP 200 and the heading "403 · Access denied"; /projects/new and /edit use a different "You are not allowed to..." panel. No data leaked (checked HTML for names, emails, notes).
8. **Minor** - KPI target `note` is displayed on the dashboard but there is no field to set or edit it anywhere in the UI (only the action accepts it). Preservation on re-save verified (note stayed after saving 4 then 5).
9. **Cosmetic** - /admin/users: per-person edit form is squeezed into the "Manage" table cell at 1024px (Title/Job role inputs truncated). Team KPI "Save" buttons are all named just "Save" (visible text), only the input has a sr-only row label. Next dev indicator overlaps the bottom-left "Add link" button (dev only).
10. **Cosmetic** - Validation messages use wavy underline text as the only styling plus an unannounced `<p>` (no role=alert/aria-live; relies on focus move to the first invalid field, which does work). Admin forms ("Saving…" status) were slow to resolve in the pane (several seconds); could not tell if throttling or server.
